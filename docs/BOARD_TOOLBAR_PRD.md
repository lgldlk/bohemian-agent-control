# Agent 画板工具与分组功能 PRD

- **状态**：评审稿（基于现有代码重新评估）
- **版本**：v0.2
- **范围**：画布 Toolbar、任务分组、文字、便签与画板整理
- **关联代码**：`src/board/EvidenceBoard.tsx`、`src/board/groupFrameEditor.ts`、`src/board/groupSync.ts`、`src/board/boardSync.ts`、`src/board/boardArrangeEditor.ts`、`src/board/boardArrange.ts`、`src/space/spaceStore.ts`

## 1. 本次重新评估的结论

上一版把文字和便签过早归类为低频白板工具，也低估了“组”在产品中的职责。这次结合现有代码重新判断，结论调整如下：

1. **分组是 Agent 工作空间的核心组织能力，必须保留并让用户容易发现。**但“分组”是任务操作，不是一个任意画矩形的绘图工具。它应通过选中任务后的上下文动作、快捷键和空间分组入口完成。
2. **文字和便签都应保留在常用工具中。**它们分别服务于轻量标签/标题和带背景的上下文记录，不应该和任务卡混为一谈，也不必强行合并成一个对象。
3. **整理画板仍是核心能力，但需要尊重人工放置的文字、便签和锁定对象。**当前整理算法只规划任务卡、终端和 frame；在完善注释对象的布局保护之前，不应宣传整理会自动整理所有画布内容。
4. **不提供手动连接工具。**任务卡和终端在创建时已经自动连线，用户不需要再画箭头。已有连线仍可选择和删除。
5. **通用白板工具进入统一二级菜单。**画笔、橡皮擦、图片、普通几何图形和普通 frame 不占常驻位，但可从“更多工具”打开。矩形不能替代业务分组框。

推荐的基础画布工具栏：

```text
[选择] [平移] | [文字] [便签] [业务分组] | [整理 ▾] [更多工具 ▾]
```

“业务分组”在选中 Agent 时将其编成一组；没有选择时在当前视口中心创建空业务组并进入命名。原生 frame 继续保留在“更多工具”，只作为自由画板容器。

当一个或多个任务卡被选中时，在工具栏附近或对象上下文区域显示：

```text
[编成一组] [移出分组] [整理这个组（选中组时）]
```

“添加 Agent / 添加已有任务”继续走现有空间添加流程，不重复做成另一种普通卡片工具。

## 2. 产品背景与问题

Bohemian Agent Control 的画板是 Agent、任务、终端和工作上下文的空间，不是通用绘图软件。用户除了查看任务和打开终端，还需要：

- 按项目或工作主题把 Agent 任务组织成组；
- 在组旁边写标题、解释、下一步和临时想法；
- 用便签保留可视化的上下文，不把每条说明都做成 Agent 任务；
- 在任务关系和人工布局之间保持清晰；
- 在内容变多之后整理任务布局，而不破坏人工添加的上下文。

现有工具栏直接使用 tldraw 默认完整工具集，绘图能力比任务能力更显眼；与此同时，任务分组已经有多套操作入口，文字和便签也是真实可创建、可编辑、随画板持久化的对象。需要治理的是入口层级和对象规则，而不是简单删掉非任务形状。

## 3. 现有能力与当前边界

### 3.1 分组能力现状

当前“组”不是一个孤立的 frame：

- `spaceStore` 保存分组名称、任务 ID 列表和折叠状态。
- 白板中的 tldraw frame 是分组的可视化投影，frame meta 中保存 group ID。
- 选中任务卡后，可以通过上下文操作栏或 Cmd/Ctrl+G 编组；框选本身不会自动建组。
- 选中分组或组内任务卡后，可以执行“移出分组”；删除 frame 会把子节点移回画布，而不是删除任务卡。
- 空间面板支持创建、重命名、折叠和删除分组，也支持向指定组添加任务。
- 在命名 frame 中添加任务/终端时，frame 可扩展以容纳内容。
- 整板整理和组内整理都会参与 frame 的位置或尺寸调整。
- 分组和任务归属会通过 board 与 space 同步逻辑保持映射。

**关键语义**：分组代表用户对 Agent 任务的归属和组织；frame 是这个分组在画板上的容器，不是随手画出的矩形。

### 3.2 文字和便签现状

- tldraw 默认 toolbar 已经包含文字工具和便签工具。
- 文字和便签是原生画板 shape，可编辑、移动、删除，并随当前画板文档持久化。
- 它们可以作为画板内容出现在 frame 内；frame 扩容逻辑会测量非箭头的子形状。
- 但 space 分组同步只从 frame 子节点读取任务卡 ID；文字和便签不会成为空间任务，也不计入任务数。
- 当前画板搜索只检索任务卡属性，不检索文字或便签正文。
- 当前自动整理只读取任务卡、终端和 frame，不会为文字/便签计算新位置；组内整理缩小 frame 时也没有将这些注释纳入最终尺寸计算。

因此文字/便签已经是有持久化能力的画布内容，但它们还没有完全接入搜索和自动整理规则。这是需要补齐的产品边界，不是把它们从 toolbar 移除的理由。

### 3.3 当前工具栏与整理现状

- 一级工具栏放选择、平移、文字、便签、整理和更多工具。
- 整理使用一个图标打开整板/当前组二级菜单；画笔、橡皮擦、图片、几何图形和普通 frame 收入更多工具菜单。箭头不提供手动入口。
- 整理算法按工作目录/项目和 Agent 类型组织任务卡，并布局关联终端。
- 整理操作有 history stopping point；任务卡或终端锁定时不会被布局计划移动。
- 当前算法并不把任意文字、便签和其他装饰 shape 当成布局对象或障碍物；需在工具栏治理后补充保护规则。

## 4. 目标与非目标

### 4.1 目标

- 让组、任务、终端和工作上下文成为画板的一级产品概念。
- 让文字和便签继续易于创建，同时清楚区分它们的用途。
- 避免普通 frame/矩形被用户误认为任务分组。
- 让画板整理只自动重排适合自动管理的 Agent 节点，保留人工内容。
- 将低频绘图能力从一级入口降级，但不影响已有文档里的 shape 显示和编辑。
- 让添加任务、编组、注释和整理各有明确入口及可预期结果。

### 4.2 非目标

- 把画板建设为完整通用白板或设计工具。
- 让便签成为 Agent 任务、空间任务或 Agent 生命周期实体。
- 提供手动箭头工具，或让连线改变 Agent 执行顺序。
- 为 V1 建设协同编辑、评论线程、富文本知识库或图片资产管理。
- 让自动整理任意重排文字、便签、图片和自由绘制内容。

## 5. 用户与关键场景

### 场景 A：按工作主题组织 Agent

用户选择一组任务卡，创建或加入一个命名分组。分组中可以同时保留 Agent 任务、终端和说明性便签。

### 场景 B：为一组任务补充上下文

用户在组内放一个标题或说明文字，并用便签写风险、假设或待确认事项。这些内容用于人理解，不会变成 Agent 状态或执行指令。

### 场景 C：添加新任务到某个组

用户从空间面板的组入口或画布空白处打开现有添加流程，启动 Agent 或将已有任务添加到空间，并指定所属组。

### 场景 D：整理任务，但保留手工注释

用户执行整板或组内整理。任务卡和终端按规则重排，便签和文字保持原有位置；系统要避免把任务卡移到注释上，也不能因 frame 缩放而把注释裁出组外。

### 场景 E：查看任务和终端的已有关系

任务卡打开或拆出终端时，系统自动画出连线。用户不需要也不应该从工具栏手动创建这种关系。

## 6. 产品原则

1. **组是业务实体，不是几何图形。**创建组、重命名和删除组遵循分组语义；普通矩形不能创建或冒充组。
2. **文字和便签是工作上下文。**它们属于画板，但不是任务，不进入 space task count 或 Agent 生命周期。
3. **机器整理与人工布局分工。**系统整理任务卡和终端；用户放置的说明内容默认不被机器移动。
4. **容器成员关系要清晰。**放在 frame 中的文字/便签是画板上的组内内容，但只有任务卡构成 space 里的任务成员列表。
5. **安全地批量修改。**整理、编组、移出分组均需一次性撤销；锁定对象与固定注释不被覆盖。
6. **不制造重复入口。**已有空间添加流程、任务卡上下文操作和组面板承担的职责不应再重复堆入工具栏。

## 7. 目标信息架构

### 7.1 基础画布 Toolbar

推荐：

```text
[选择] [平移] | [文字] [便签] [业务分组] | [整理 ▾] [更多工具 ▾]
```

优先顺序：

- **选择 / 平移**：导航和操作的基础工具。
- **文字 / 便签**：添加画板上下文的常用入口。
- **业务分组**：选中 Agent 时编组；无选择时在当前视口创建空业务组。
- **整理**：一个主图标，菜单内提供“整理整个画板”和“整理选中的组”。
- **更多工具**：统一承载画笔、橡皮擦、图片、线、强调、普通 frame、几何图形和激光笔。

箭头不出现在一级或二级工具中，因为任务卡与终端已经自动连线。普通 frame 与业务分组仍需保持明确区别。

### 7.2 组操作的位置

组操作是核心能力，但它是**选中对象后的命令**，不需要永久占用一个绘图工具位：

- 选中一个或多个任务卡：显示“编成一组”。
- 选中组内任务卡或分组 frame：显示“移出分组/解散分组”。
- 选中一个 frame：“整理”菜单中的“整理选中的组”变为可用，同时显示其他组级操作。
- 快捷键 Cmd/Ctrl+G 保留为编组快捷方式。
- 空间面板继续负责分组的创建、重命名、折叠、删除和指定组添加任务。
- 右键菜单可提供同一组操作作为辅助入口。

避免把通用 tldraw “Frame”工具命名或包装成“创建分组”。如果要创建空组，应走明确的“新建分组”流程，并同步空间分组与画布 frame。

### 7.3 添加任务与全局 Header

- Header 负责视图切换、搜索、设置、语言切换，以及直接向画板添加一个空终端。会话数据已有自动轮询和事件刷新，不再提供重复的 SYNC 主按钮。
- 添加 Agent 或添加已有任务使用现有 SpaceAddModal 流程：空白处双击可快速打开；空间面板和卡片视图也能选择目标组。
- 画布 toolbar 不另造一个视觉相似的任务卡或“便签式任务”入口。

### 7.4 Agent 快速导航

- 画板左上角提供可展开的 Agent 导航入口，收起时仅显示当前画板 Agent 数量。
- 展开后只列出当前画板中的任务卡，按画板 frame 分组，未分组内容放在最后。
- 支持按 Agent 名称、项目、工作目录、模型、Agent 类型和组名搜索，并提供全部、活跃、待处理筛选。
- 单击 Agent 选择并平滑定位对应卡片；双击或终端按钮打开对应终端。
- 导航器只负责预览与定位，不提供删除、移动分组或创建 Agent，避免成为第二套 SpacePanel。

### 7.5 右键菜单治理

- 右键菜单按空白画布、Agent 卡片、终端、业务分组、系统连线、自由内容和混合选择分别提供动作。
- Agent 卡片不提供通用复制、剪切、转换和删除，只提供终端、会话、移动分组、编组/移出分组与“从画板移除”。单卡不显示“编成一组”。
- 终端不提供 Duplicate、普通 Delete、进入终端或拆分等重复入口；只提供定位 Agent、按状态重启/恢复、复制会话和“关闭并移除终端”。
- 业务分组只提供添加 Agent、整理、重命名和“解散分组，保留内容”。
- 文字、便签、图片和普通几何图形保留复制、创建副本、图层、锁定和删除能力。
- 系统自动连线只提供定位两端；在建立可恢复的隐藏状态前，不提供“隐藏连线”。
- 混合选择只提供共同安全的会话复制和聚焦动作。

## 8. 工具和对象定义

### 8.1 选择与平移

- 默认进入选择模式。
- 支持选择任务卡、终端、frame、文字、便签和已有连线。
- 支持多选任务卡并触发组操作。
- 平移画布不改变对象页面坐标、不产生撤销记录。

### 8.2 文字

**定位**：轻量的自由文字，用于标题、分区标签、短说明和画布注释。

**保留理由**：文字比便签更轻，不需要背景容器；适合标记某一区域、给一组任务加标题或增加短提示。

**规则**

- 文字 shape 与任务卡视觉层级不同，不显示 Agent 状态、运行状态或任务计数。
- 双击可编辑；选择后可移动、删除、调整样式。
- 可以被放在 frame 中，作为组内可视内容；不计入组的任务数。
- V1 不因“整理画板”自动移动文字。
- 搜索是否覆盖文字正文列入 V1.1；至少不能让用户误以为画板搜索已包含所有文字。

### 8.3 便签

**定位**：带有清晰背景和视觉容器的上下文记录，用于假设、风险、临时待办、决策和待确认事项。

**规则**

- 便签是画板内容，不是任务卡；不启动 Agent、不进入 task count、不改变 Agent 状态。
- 便签可编辑、移动、改样式和删除，支持撤销。
- 放进 frame 时作为组内内容随 frame 一起组织；是否归属某个空间组仍不等同于任务成员归属。
- 整理任务时默认视为人工锚定内容，不被自动重排。
- V1.1 可评估便签与任务卡的显式关联；V1 不自动将便签文本作为 Agent prompt。

### 8.4 文字与便签的边界

| 需求 | 使用文字 | 使用便签 |
| --- | --- | --- |
| 标题、区域名称、短标签 | 是 | 可用但偏重 |
| 假设、风险、临时待办 | 不推荐 | 是 |
| 多行上下文记录 | 可用 | 推荐 |
| 进入空间任务列表 | 否 | 否 |
| 自动参与任务整理 | 否 | 否 |
| 自动作为 Agent 指令 | 否 | 否 |

### 8.5 连线

- 不在 toolbar 提供箭头或“连接”工具。任务卡与终端的关系在节点创建时自动生成。
- 已有连线可以被选择和删除，但不进入分组任务计数，也不影响布局测量。
- 连线不改变 Agent 执行顺序，也不触发 Agent。
- 后续如果要表达依赖、阻塞或产出，需另行定义数据模型，不能直接把通用箭头工具放回一级工具栏。

### 8.6 分组与 frame

#### 用户可见行为

- 编组至少一个选中的任务卡后，系统创建有名称的分组，并将卡片放入该分组。
- 多选任务卡编组时，分组框从卡片边界和留白计算初始位置与尺寸。
- 用户可以在空间面板创建空分组；之后添加任务时，白板显示对应 frame。
- 向组内添加 Agent 后，系统按 Agent 类型和每行容量重新整理该组，优先填满已有行的空位，并自动聚焦新增卡片。
- 新 Agent 的终端尚未出现时，布局仍预留标准终端空间，避免终端随后创建时覆盖下一种 Agent。
- 用户可以重命名分组，名称在空间面板和画布 frame 标题保持一致。
- 用户把任务移出分组或解散分组时，任务仍然存在，只改变归属。
- 删除分组的行为应明确为“解散/移除分组并重新归属任务”，绝不能暗示删除 Agent session。
- 文字和便签可以在画布上视觉归属于 frame，但它们不进入 `spaceStore` 的任务成员列表。

#### 入口

- 选中任务后的“编成一组”上下文动作和 Cmd/Ctrl+G。
- 空间面板“新建分组”、重命名、折叠、删除和组内添加入口。
- 右键菜单作为辅助入口。
- 不提供普通矩形替代分组的操作。

#### 需要统一的行为

- 在画布中拖动任务卡进出 frame 后，space group membership 与画布投影一致。
- 选中 frame 后能发现组级操作，包括“整理这个组”。
- 解散分组只删除容器，不删除 frame 中任务卡、终端、文字和便签；对象返回画布层。
- 删除空间分组时，必须同步处理对应 frame，不能只改 `spaceStore` 后留下会被同步逻辑重新读回的旧 frame。
- 组名、组成员数量和空组状态在空间面板与画布中保持一致。

## 9. 整理画板规则

### 9.1 自动整理管理的对象

默认自动管理：

- 任务卡；
- 与任务关联的终端；
- 分组 frame 的位置和尺寸。

默认不自动管理：

- 文字；
- 便签；
- 连接线；
- 图片和自由绘制内容。

### 9.2 人工内容保护

整理功能完善后需要满足：

- 文字和便签位置保持不变，等同于整理中的固定锚点。
- 整理后的任务卡和终端不能覆盖固定文字或便签；布局规划必须将这些对象的范围视为占用区域。
- 组内整理后 frame 尺寸需包含所有保留在组内的内容，不能缩到文字或便签外面。
- 锁定的任务卡、终端、文字和便签均不移动；如果锁定对象影响 frame 布局，应保留其边界并避让。
- 若固定对象导致无法得到无重叠布局，优先扩展组或增加间距，不得移动或丢弃注释；仍无法完成时给出清楚反馈。
- 一次整理形成一个撤销历史点；撤销恢复任务卡、终端、frame 和相关属性。

### 9.3 整理范围和操作入口

- **整理画板**：按当前任务、工作目录、Agent 类型和分组规则整理整个页面。
- **整理这个组**：仅整理选中 frame 内的任务卡和终端，frame 的页面位置不变。
- 组内整理不得将组外任务吸入组内。
- 整理空白画板或空组时给出明确禁用态或提示，不允许按钮无响应。

### 9.4 整理反馈

操作成功后用轻量 toast 表示整理范围和结果，例如：

```text
已整理 12 个任务，保留 3 个锁定对象和 2 条便签
```

若没有可整理任务：

```text
当前范围内没有可整理的任务
```

## 11. 成功指标与体验护栏

### 成功指标

- 用户能在不读说明的情况下区分任务卡、分组、文字和便签。
- 用户能快速创建分组，并在画布和空间面板中看到一致结果。
- 用户使用文字或便签添加上下文时，不会误以为它们进入 Agent 任务列表。
- 用户执行整理后，任务布局更清楚，原有便签和文字仍在且没有被遮挡。
- 组内整理不会让任务或注释离开该组的可视边界。

### 体验护栏

- 删除便签或文字不影响任何 Agent session。
- 删除任务卡/移出分组不等于删除 Agent session。
- 删除/解散组不得丢失组内任务或其他画布内容。
- 整理不移动锁定对象、不删除对象、支持一次撤销。
- 工具收敛不破坏已保存的原生 tldraw shape。
- 不把便签正文自动注入 Agent prompt。

## 13. 验收清单

### Toolbar 与入口

- [ ] 默认工具栏常驻选择、平移、文字、便签、业务分组、整理和更多工具。
- [ ] 业务分组按钮在有 Agent 选择时编组，无选择时在视口中心创建空业务组。
- [ ] 原生 frame 只存在于更多工具中，不写入 `spaceStore`。
- [ ] “整理”只使用一个图标，并提供整板/当前组二级菜单。
- [ ] 未选中分组时“整理选中的组”禁用。
- [ ] 工具栏没有箭头或手动连接入口。
- [ ] 编组/解组操作在选中任务时可发现，不与普通 frame/矩形混淆。
- [ ] 画笔、橡皮擦、图片、线、几何形状和普通 frame 可从更多工具打开。
- [ ] 左上角 Agent 导航器只显示当前画板任务卡，并按 frame 分组。
- [ ] Agent 导航器支持搜索和状态筛选，单击可定位，终端按钮可打开终端。
- [ ] 导航器操作不会触发画布拖拽、框选或双击添加。
- [ ] 右键菜单根据对象类型变化，业务对象不会出现 Duplicate、Convert 或含义不清的 Delete。
- [ ] Agent、终端和分组的危险操作使用明确文案，并且不会隐式删除 Agent session。
- [ ] 空白画布右键只保留添加 Agent、新建分组、粘贴和整理画板。
- [ ] 自由画板内容仍可使用复制、创建副本、图层、锁定和删除。
- [ ] 运行中的终端不显示重启；只有已退出或缺失时显示恢复动作。
- [ ] 系统自动连线不提供不可恢复的“隐藏”操作。

### 分组

- [ ] 选中任务卡编组会创建有名称的业务分组 frame。
- [ ] 创建、重命名、折叠、删除/解散分组后，空间面板与画布同步。
- [ ] 解散分组只移除容器，不删除任务卡、终端、文字或便签。
- [ ] 组内文字/便签可以被选中、移动和编辑，但不计入 space task count。
- [ ] 添加任务到组后，frame 能容纳新增任务及相关终端。
- [ ] 新增 Agent 会填入对应 Agent 行的最早空位，并自动聚焦。
- [ ] 终端延迟创建时不会与下一行其他 Agent 卡片重叠。
- [ ] 删除组不会让任务或 frame 因双向同步而复活或丢失。

### 文字与便签

- [ ] 文字和便签可创建、编辑、移动、删除、撤销，并随画板持久化。
- [ ] 文字用于轻量标签/标题，便签用于带容器的多行上下文。
- [ ] 文字和便签不改变任务状态、不启动 Agent、不进入任务计数。
- [ ] 删除文字或便签不会影响空间分组或 Agent session。

### 整理

- [ ] 整板和组内整理按现有项目/目录及 Agent 规则排列任务和终端。
- [ ] 文字和便签在整理后保持位置且不会被新布局覆盖。
- [ ] frame 调整尺寸后仍包含其组内固定内容。
- [ ] 锁定任务卡、终端、文字和便签不移动；布局保留其范围。
- [ ] 一次整理可通过一次 undo 恢复全部位置和尺寸。
- [ ] 空白画板、空组和全部锁定等情况均有明确反馈。

## 14. 需要评审确认的问题

1. 组内整理时，文字和便签应作为“固定障碍物”保留，还是允许用户显式选择“连注释一起移动”？本稿默认固定。
2. 空间面板删除分组后，组内任务默认回到“未分组”，还是并入其他指定分组？本稿建议回到未分组，并先明确告知。
3. 文字和便签是否需要被顶部搜索检索？本稿建议 V1.1 加入，并区分搜索结果类型。
4. 任务与终端之外，是否还需要人工关系？本稿默认不需要，连线只由系统在创建节点时生成。
5. 更多工具中的普通 frame 是否需要改名为“自由框架”，进一步避免与业务分组混淆？

## 15. 最终产品判断

画板的核心不只是 Agent 任务卡。一个可用的 Agent 工作空间还需要**分组来组织工作，文字来标明结构，便签来保存上下文，整理来恢复清晰布局**。任务和终端的连线由系统默认生成，不再占一个工具位。

因此，本次不再建议移除文字和便签，也不把连接放回一级工具栏。正确的收敛方式是：

```text
一级工具：选择 / 平移 / 文字 / 便签 / 业务分组 / 整理 / 更多工具
业务分组：选中 Agent 时编组 / 无选择时新建空业务组
整理二级菜单：整理整个画板 / 整理选中的组
更多工具：画笔 / 橡皮擦 / 图片 / 线 / 强调 / 普通 frame / 几何图形 / 激光笔
对象上下文：编组 / 移出分组
不提供入口：手动箭头
```

组操作不和自由绘图竞争位置；文字与便签保留，但必须明确它们是持久化的画板上下文而不是任务事实；自动整理只管理 Agent 节点，同时尊重这些手工内容。
