# Agent Token 用量看板 PRD

- **状态**：已作为内置插件接入独立 `USAGE` 页面；不提供 toolbar/topbar 按钮或画板侧栏弹窗。
- **版本**：v0.3
- **适用范围**：本机 Pi、Codex、Claude Code 会话的 Token 用量查看。
- **参考**：`reference/juejin-usage` 仅作为信息架构参考，不引入其运行时、登录、排行榜或云同步能力。

## 1. 产品目标

用量看板将本机会话文件中已有的 Token 记录汇总为一个只读视图，帮助用户回答：

- 哪些 Agent、模型和工作目录使用量最高；
- 哪些会话有用量记录，哪些会话缺少记录；
- 从用量明细能否定位回画板上的任务卡；
- 在来源提供完整字段时，输入、输出和缓存分别占多少。

它只展示用量，不提供成本、价格、预算、账单或费用估算。累计 Token 不能推导出可靠成本，因此不得用平均单价或猜测价格生成金额。

## 2. 产品边界

### 2.1 包含

- Pi、Codex、Claude Code 三种已接入 Agent。
- 会话累计 Token、输入/输出/cache 拆分（来源提供时）。
- TODAY、7D、30D、90D 范围筛选，并持久化最近选择。
- Agent 多选筛选，联动概览、趋势、热力图、分布图和会话列表。
- 按 Agent、模型、文件夹和会话汇总。
- 从会话明细定位画板任务卡。
- 独立 `USAGE` 页面。

### 2.2 不包含

- 成本 Dashboard、模型价格目录、月预算和费用告警。
- “累计 Token × 平均单价”等费用估算。
- 云同步、账号登录、公开排行和分享卡片。
- Prompt、回复正文、工具参数、API Key 或主机身份采集。
- 因打开终端、移动卡片或删除画板投影而修改用量记录。

## 3. 数据契约

任务 DTO 可以携带：

```ts
interface AgentUsageBreakdown {
  input: number;
  output: number;
  cacheRead: number;
  cacheWrite: number;
}

interface UsageFields {
  tokenCount?: number;
  usageBreakdown?: AgentUsageBreakdown;
}
```

规则：

- `tokenCount` 是会话累计值，不代表所选时间范围内真实新增量。
- 缺失用量与显式 `0` 必须区分；缺失不能伪装为 0。
- `usageBreakdown` 只在来源能可靠解析时提供。
- Claude Code 对相同 message/request 的重复快照按最大累计值去重。
- Codex `token_count` 使用最新累计快照，不能把多个累计事件直接相加。
- Pi 按 session 中可识别的 message、usage、compaction 和 branch summary 用量累加。
- 会话文件路径只保留在服务端，不进入前端 DTO。

## 4. 页面结构

### 4.1 概览

- 所选范围内可读取的会话累计 Token。
- 有记录与缺失记录的会话数量。
- 有拆分数据时展示输入、输出和缓存合计。

### 4.2 活跃日图

当前任务 DTO 只有会话累计值和最后活跃时间，因此图表将整个会话累计值归到最后活跃日。界面必须明确标注：这是会话活动概览，不是逐日增量或账单。

- Hover 或键盘聚焦柱体时显示日期、Token 和会话数量。
- 点击柱体切换日期筛选；再次点击同一日期取消。
- 日期筛选联动概览、分布图和会话列表。

### 4.3 用量热力图

- 展示过去 11 个月的周历网格，按本机时区排列星期与月份。
- 颜色深浅表示归档到该活跃日的会话累计 Token。
- 空白未来日期不绘制；没有记录的过去日期使用最低色阶。
- 热力图与活跃日图使用相同口径，不代表真实逐日增量。
- Hover 或键盘聚焦日期格显示精确日期和 Token Tooltip。
- 点击日期格切换整页日期筛选，选中日期显示高亮边框和可清除筛选条。

### 4.4 维度汇总

- 按 Agent：环形饼图，中心显示累计用量。
- 按模型：实心饼图，突出最高用量模型。
- 按文件夹：多环径向饼图，复用画板整理使用的工作目录键。
- 三类图表使用同一蓝色系，但采用不同图形结构；图例同时显示用量、占比、会话数量和缺失记录数量。
- Hover 扇区或图例时突出当前分类并显示精确用量与占比。
- 点击图例隐藏或恢复分类，图表合计和占比按当前可见分类重新计算。
- 分类超过 5 项时默认折叠，可展开查看全部；超过图表颜色容量时合并为“其他”。

### 4.5 会话明细

- 支持搜索、Agent 筛选、用量排序和最近活跃排序；
- 展示会话标题、项目、模型、最后活跃时间和累计 Token；
- 缺少记录时显示 `—`；
- 点击行只定位已有任务卡，不自动创建或移动卡片。

## 5. 状态与所有权

- 原始会话历史由 API server 读取，前端不得直接扫描 Agent 文件。
- `tokenCount` 和 `usageBreakdown` 是服务端事实。
- tldraw shape 只是投影，不拥有或删除用量事实。
- 终端是否打开、PTY 是否存活和 Token 用量相互独立。
- 插件通过宿主提供的任务快照和定位 capability 工作，不直接访问 terminal client、PTY API 或核心 store。
- Token Usage 插件只贡献懒加载的 `pages` 页面，不注册 toolbar、topbar 或 panel contribution。
- 页面入口和渲染由通用插件宿主发现；`App.tsx` 不包含 `token-usage`、`dashboard` 或 Usage 专属 view。

## 6. 验收标准

1. 有 Token 记录的会话显示累计值，缺失记录显示 `—`。
2. 显式 `tokenCount: 0` 被计为有记录，不计入缺失数量。
3. Codex 多个累计快照只使用最新值，不重复累加。
4. Claude Code 相同 message/request 的更新快照不会重复累计。
5. 输入、输出和缓存拆分之和与来源记录一致。
6. 连续刷新不会让相同会话的累计值无故增长。
7. 按 Agent、模型和文件夹汇总与会话列表一致。
8. 点击会话可以定位已有画板任务卡。
9. 页面不出现成本、价格、预算或估算金额。
10. 页面纵向滚动和热力图横向滚动使用与热力图一致的主题滚动条。
11. 损坏或不可读的会话文件不会导致整个 Usage 页面失败。

## 7. 后续方向

若未来需要真实的逐日或逐小时用量，应新增带事件时间和稳定去重键的 `UsageRecord` ledger，再从 ledger 聚合。不得继续把会话最后活跃日当作真实消耗日期。
